# Domain vocabulary

Shared language for specs, code and reviews. When a term here and a name in code disagree, one of them is wrong.

| Term | Meaning |
| --- | --- |
| **User profile** | The local owner of all data. Single user today; modeled so more profiles can exist later without a login system. |
| **Channel** | A brand: niche, themes, aesthetic, language, target country and a default persona. Owns one or more network accounts. |
| **Network** | A social platform: YouTube, TikTok, Instagram Reels, X, Kick. |
| **Network account** | A channel's profile on one network: credentials (in Windows Credential Manager), metadata defaults and render preset overrides. |
| **App credentials** | The client id and secret of the OAuth app the user registered on a network (Google Cloud OAuth client, TikTok app, Meta app), entered once in Settings and kept in Windows Credential Manager per user profile. Bardo ships none of its own (ADR-0008). |
| **Network connection** | A network account signed in through the network's OAuth with the user's app credentials: its tokens in Windows Credential Manager per network account, and in SQLite only the connected identity, scopes and expiry. *Reconnect needed* when the network refuses a refresh; disconnecting revokes the token. |
| **Persona** | A reusable narrator identity owned by the user profile: voice reference, tone, script style and generation presets. Assigned to a channel as default and overridable per video. |
| **Voice reference** | A pointer to a voice held by a voice provider (e.g. an ElevenLabs voice id). The voice itself never lives in Bardo. |
| **Persona package** | A persona exported to a file (`.bardo-persona`, versioned JSON): name, tone, script style, presets, voice reference and the realistic voice flag. Never audio, keys or local ids. Importing adds a new persona to the library; a newer format version than the app reads is refused. |
| **Voice flag** | Marks an imported persona whose voice is not known to be in the user's provider account: *unchecked* until a voice listing looks it up, *unavailable* when the listing lacks it. A flagged persona cannot narrate; a listing that has the voice, or picking a listed voice, clears it. |
| **Niche** | A content market (e.g. "space history"). Scored for competition and trend. |
| **Market** | A channel's target country plus content language. Market data is fetched and cached per niche and market. |
| **Niche research** | A job that fetches recent uploads for a channel's seed niches (YouTube Data API) and scores each niche. Results are cached with their fetch date for 7 days; refresh fetches again. |
| **Competition** | 0–100 score of how hard a niche is to stand out in: upload volume, channel size and few views per upload push it up. |
| **Trend** | 0–100 score of how fast a niche's recent uploads gather views (median views per day). |
| **Opportunity** | The average of trend and room left by competition (100 − competition). Research results rank by it. |
| **Theme** | A specific video idea inside a niche: a title and an angle. Claude suggests themes, the decision engine ranks them, and the user edits, discards or approves each one. |
| **Interface theme** | How the app itself looks: colors, corner radius, border width and font, never layout. Ten ship: four base themes (Paper, Sand, Graphite, Slate), high contrast light and dark, and four terminal themes (Black Gold, Brass, Phosphor, Phosphor Light) with square corners and a monospace font. Not a **Theme**, which is a video idea. |
| **Theme preference** | A profile's choice of interface theme: follow Windows (a light and a dark theme, switched as Windows switches) or always the same theme. Defaults to following Windows with Paper and Graphite. |
| **Layout** | Where every screen places its parts, chosen per profile in Settings › Appearance: Workspace (a sidebar by pillar, a stepper over the project, cards with the inspector beside them; the default) or Studio (top tabs, compact stage tabs, tables with the inspector in a bottom panel, a status bar). A layout only places things: every screen builds the same parts (header, stages, toolbar, notices, collection, inspector, content, aside, figures, sections) and each layout arranges them, so a new layout is a new variant and arrangement and nothing else. The editor is the same in every layout. Every UI change has to work in every layout; from issue #61 on, each UI slice carries "works in every layout" as an acceptance criterion. Not an **Interface theme**, which colors things and never moves them. |
| **Theme ranking** | The decision engine's reasons for a theme: fit (with the channel), trend (demand now) and competition (how crowded the angle is), each a 0–100 score with a confidence, plus past performance once the channel has history. Priority weighs fit 40%, trend 35% and room left by competition 25%; past performance takes 5% per published video with a first week (up to 25% from five), the other three sharing the rest in the same proportions. The ranking's confidence is its least certain reason. Editing a theme's text drops its ranking until it is ranked again. |
| **Past performance** | How the channel's own published videos did, as the theme ranking reads it: each video project's **first week** and where it stands against the channel's usual (the median first week: far below, below, about, above, far above). The engine reads the newest 40 and scores how an idea would do next to the ones most like it; the reason shows the average first week of the channel's videos in the theme's niche (or of all its videos, when the niche has none). Fixed when the ranking job starts. Ideas ranked before the channel had history keep their ranking until the user ranks again. A channel with no video that has a first week ranks exactly as before. |
| **First week** | A publication's views seven days after it went live, read off its metrics snapshots: in a straight line between the snapshots around day seven; along a square-root curve from zero when the first snapshot comes in the second week, or projected along it from the newest snapshot of the first week (at least two days old). A publication first synced after its second week, with no earlier snapshot, has no first week. A video project's first week adds up its publications'. |
| **Narration** | A video project's script read aloud by its persona (the project's own, else the channel's default; ElevenLabs), saved as an MP3 in the project folder with its word timings, the voice and presets used, the model and what the provider billed. Long scripts are read in parts and joined. It belongs to the text it read: once the script changes, the narration is stale until generated again. |
| **Word timings** | When each word of the narration is spoken. Comes with generated narration (the provider times each character; Bardo maps those onto the script's words); computed by alignment for imported audio. Drives the highlighted word in playback, captions and cut snapping. |
| **Project folder** | Where a video project's media lives on disk: `%LOCALAPPDATA%\Bardo\projects\<project id>`. The database keeps file names; the files stay where the user and other tools can reach them. |
| **Template** | A versioned, editable prompt/plan used to generate a script, title, description or media prompt. Its instructions and prompt hold `{{variable}}` placeholders from a fixed set per kind; saving changed text creates the next version and old versions stay readable. |
| **Script** | What the narrator says in a video project. Generated by Claude from the script template, then edited freely by the user. A regenerated script waits for review next to the current one, which stays until the user accepts the new one. |
| **Scene plan** | A video project's narration split into scenes by Claude from the image prompt template. Scenes start on sentences and run back to back from the first word to the end of the narration, so each scene's time comes from the word timings. One plan per project; planning again replaces it (and its images, after the user confirms). It belongs to the narration it was planned on: a new narration makes it stale. |
| **Scene** | A stretch of the narration with one image: its start and end, the narration spoken over it, Claude's image prompt and the user's edited one, its image, a newer image waiting for review, and why its last drawing failed. Drawing a scene again keeps the current image until the user accepts the new one. A scene may also have a clip, with its own motion prompt and video model. |
| **Image generator** | Draws one image from a prompt. Implemented by Nano Banana (Gemini image model), 16:9 at 2K. A request the provider's safety rules decline fails that scene only. |
| **Clip** | A short video a video provider makes from a scene's image (image to video), saved as an MP4 in the project folder with its generation, length and the image it animated. As long as the scene is narrated, within the lengths the model allows. A new clip waits for review like a new image; a scene without a clip keeps its still image. A clip of an image the scene no longer uses is stale. |
| **Motion prompt** | How a scene's image moves in its clip: subject, action, camera. The scene's image prompt unless the user writes one. |
| **Video model** | The provider model that makes clips, e.g. Kling 3.0 through Higgsfield, or Veo 3.1 Fast at 720p through Google. A channel picks the one its scenes use (the provider's default otherwise); any scene can pick another. |
| **Clip generator** | Makes clips asynchronously: hand over the image, submit, poll, download. Implemented by Higgsfield and by Google (Veo and Gemini Omni Flash, on the Gemini key; the image goes inline with the submission). The job saves the provider's request ids before waiting, so a restart polls the same requests instead of paying again. |
| **Generation** | The provenance of a generated asset: provider, model, the final prompt sent, the template version and the tokens used. Never changes; editing the asset leaves its generation as it was. |
| **Video project** | One video in production: script, generated assets, timeline, per-network metadata and publications. Starts when the user approves a theme and stays linked to its channel, niche and theme. |
| **Asset** | Any media file in a project: generated image, video clip, narration, music, SFX or imported file. |
| **Imported media** | Audio or video the user brings into a video project (music, SFX, footage). Bardo reads it with ffmpeg first, refuses what it cannot play, and copies it into the project folder; the user's file is never changed. Audio goes on the music or SFX track, footage on the video track, where its picture plays without its sound. |
| **Music prompt** | The text Claude writes, from the music prompt template, for the user's own music tool. Bardo does not make music: the user edits and copies the prompt, makes the track elsewhere and imports it. Generating again replaces the prompt, edits included. |
| **Timeline** | Ordered clips on video and audio tracks, with cuts, gain, fades and captions. The video track is magnetic (clips run back to back, so removing or reordering one moves the ones after it); audio items sit where they are put, with silence between them. Starts as the rough cut built from the scene plan and narration. |
| **Cut** | The user's edits to a timeline (split, trim, move, reorder, delete), saved as they are made and undoable within the editor session. A cut belongs to the scene plan and narration it was made on: a new plan or narration starts it over from the rough cut. Cuts snap to the narration's word boundaries unless snapping is off. |
| **Cut suggestion** | A point where the decision engine thinks the picture could cut, with a 0–100 score, a confidence and its reasons: a sentence end, a pause of 300 ms or more, a scene change in the script, a topic shift. Candidates are the open points of the cut: those not already cut and at least a second from a cut or a clip's end. The script goes to the engine in stretches that fit its context, the points marked in the text. Suggestions are saved in narration time, so they outlast edits; nothing changes until the user accepts one, which cuts the picture like a manual split (undo takes it back). Rejected ones leave the timeline until the user asks again, and asking again replaces the whole set. Those under the profile's floor (0.50 unless changed) are hidden unless the user shows them. |
| **Mix** | How the timeline's audio tracks (narration, music, SFX) are balanced: each track's level, mute and solo, plus music ducking. Part of the timeline, saved with the cut and undoable; preview and render play the same mix. A soloed track silences every track that is not soloed. Fades belong to each audio item (fade in, fade out), not to the track. |
| **Ducking** | Lowering the music while the narration speaks, by an amount the user picks (12 dB unless changed). Follows the narration's word timings as they sit in the cut: it starts lowering just before a word (150 ms), comes back up after it (500 ms), and stays down across pauses shorter than a second. On unless the user turns it off; muting or soloing the narration does not change it. |
| **Caption** | One line of on-screen text from the narration's words: grouped by length (32 characters), time (3 s) and punctuation. Captions are timed in the narration, so they show wherever the cut plays their words and go with the narration cut away. The user edits a caption's text and ends, deletes one, or turns captions off; each is an edit like any other. Burned into the picture in preview and render. |
| **Caption style** | How captions look: Clean (white with an outline), Boxed (on a dark band) or Punch (large yellow capitals). A channel's style starts each new project's captions; a project can pick another, for all its captions at once. The style is part of the cut, so a cut that starts over takes the channel's style again. |
| **Framing** | The shape of the frame a cut is made for (16:9 or 9:16) and how each clip fills it. Scene pictures are 16:9, so a 16:9 cut shows them whole; in 9:16 each clip either fills the frame with a window of its picture placed across it (centered unless moved) or fits whole with bars. Part of the cut, saved and undoable; a cut that starts over keeps its frame shape. |
| **Proxy** | A low-resolution copy of a clip (540 lines, every frame a keyframe) that preview decodes instead of the original, so playback and scrubbing stay light. Built in the background; the render always reads the originals. |
| **Render preset** | Output format per network (aspect ratio, resolution, codec, bitrate, duration limit, loudness target). Each network has a built-in one; a network account overrides single values, and the rest follow the built-in. |
| **Render** | Producing the final media file from a timeline. Irreversible in cost/time; requires review. |
| **Render review** | What the user sees before a render: the cut's length, frame, mix loudness and captions, and each network account of the channel as a target in its render preset, with its quality gates and last file. Nothing renders until the user confirms the targets they chose; a cut changed after the review is reviewed again. |
| **Quality gate** | One thing the render review flags about the cut or a target, with its reason: over the network's duration limit or no working encoder for the codec (both block that target), a reframed output, captions off, missing media, a silent mix, a mix far from its loudness target, peaks the render will limit (warnings). Measured locally from the cut and ffmpeg, not asked of the decision engine. |
| **Publication** | A render sent (or scheduled) to one network account, with its metadata and status. Requires review. |
| **Uploaded publication** | A publication Bardo sent to the network after the upload review: queued, uploading, processing, then scheduled, published, draft sent (TikTok inbox) or *restricted* (the network kept it private because the user's app is not audited); failed keeps its reason. |
| **Manual publication** | A publication the user posted by hand from an export, linked to Bardo by its post URL so its metrics can be tracked. One per project and network, and only once that network was exported. The URL must be the network's own post address (YouTube video or Short, TikTok video, Instagram reel or post, X post, Kick video or clip); short share links are refused because they hide the post id. Linking the same post again keeps its metrics; another post replaces them. A post links to one project. Its posted date is when it was linked until a sync reads YouTube's own. |
| **Video metadata** | One network's post for a video project: title, description and tags. Claude writes every network's at once from the script and each account's defaults (language, default tags, footer), with the metadata template; the user edits them. Each network's limits are domain rules (title and text length with the account's footer and hashtags counted, tag count or tag field length, `<` `>` on YouTube). Text over a limit is kept and flagged, and keeps only that network out of an export. Writing again replaces every network's metadata, edits included, after the user confirms. |
| **Export** | A ready-to-post package for manual posting: `Videos\Bardo\<project title> (<id>)\<network>\` with the network's rendered file, named after its title, and `metadata.txt` (UTF-8, Windows line ends, labels in the interface language) holding each field to paste, the visibility and, when needed, the disclosure reminder. Runs as a job, one network at a time; exporting again replaces that network's files. An export goes out of date when the network's render or post changes. |
| **Synthetic-content disclosure** | The label networks ask for on videos with a realistic synthetic voice or a clone of a real person's voice. A persona carries a "realistic voice" flag (ticked when a cloned or professional voice is picked, editable); when the project's narration was read with a flagged persona, the Publish stage and every metadata file say where each network takes the label. A recording the user imported is never flagged. |
| **Budget** | A monthly spending limit the user sets per AI provider. Reaching it makes new jobs for that provider ask for confirmation. |
| **Provider** | A paid AI or data service Bardo calls with the user's own key: Claude, ElevenLabs, Gemini, Higgsfield, TypeSafe (JEV), YouTube Data API. |
| **Provider key** | The user's API key for one provider, kept in Windows Credential Manager per user profile. Tested with the cheapest authenticated call the provider offers; masked by the redactor wherever text leaves the app (logs, stored errors, screen). |
| **Job** | A long-running task (generation, render, upload, metrics sync) in the queue, with progress, cancel and resume. |
| **Metrics snapshot** | Post-publication statistics for one publication at a point in time (views, retention, engagement and, on YouTube, estimated revenue/CPM/RPM). For a manual publication on YouTube: the public views, likes and comments; likes or comments the owner hides stay empty, not zero. |
| **Metrics sync** | A job that reads the public statistics of every YouTube manual publication with the user's YouTube Data API key, 50 posts per call (1 quota unit), and stores a snapshot of each post found. A post not found is flagged and keeps its numbers. Runs on "Sync now", after a YouTube post is linked (unless a sync is already running; the next one reads it), and when the app opens if the oldest check is older than the profile's setting (6 hours unless changed; can be off). Other networks keep only the link until their APIs are connected. |
| **Decision engine** | Answers typed questions (choice, score, yes/no) about a piece of content, with probabilities and confidence. Ranks, scores and gates; never generates content. Implemented by JEV (hosted) and, later, Laya (local). |
| **Text generator** | Writes text (ideas, scripts, prompts) from instructions and a prompt, as prose or JSON in a given schema. Implemented by the Claude API. |
